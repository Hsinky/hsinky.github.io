# newui 使用文档

> 本文档随插件发行。各组件的详细教程（说明 / 平台兼容性 / 示例代码 / API 属性·事件·插槽表）
> 位于 `uni_modules/new-ui/components/<组件名>/readme.md`，配合 IDE 提示即查即用。
> 版本变更见 `changelog.md`（最新版）与 `changeloglist.md`（完整历史）。

## 🧭 三步上手

| 步骤 | 做什么 |
|---|---|
| **① 导入** | HBuilderX 中将插件导入 uni-app x 工程，组件经 easycom 自动注册，模板直接写 n-xxx 标签，无需导入语句 |
| **② 搭骨架** | 页面用 n-page 起步：深浅主题自动挂载、原生滚动、常驻底栏与安全区自动处理 |
| **③ 接主题** | App.uvue 样式区（声明 scss）引入插件 styles 目录全局入口一次，即得全局主题类与全部设计令牌 |

> 深色跟随系统需在 manifest.json 开启暗黑支持（darkmode），未开启时恒为浅色；
> 原生导航栏 / tabbar 联动配合 theme.json 使用。

## 🧰 函数工具集

### 微信小程序分包说明

组件库为标准 easycom 源码结构，随使用者的项目由其本地编译器编译。若使用者的工程采用多分包且分包页面使用了本库组件，微信开发者工具「代码质量分析」可能出现「主包内不应存在主包未使用的JS文件」提示（列出组件附属模块文件）。成因是 uni-app x 编译器的分包放置策略（组件本体已随分包放置、附属依赖留在主包 uni_modules），并非组件库或使用方式问题；该提示为体积优化建议，不影响小程序的功能、预览、上传与发布。单分包工程不会出现。已在 HBuilderX 5.34 实测并向 DCloud 官方反馈，待编译器修复后自然消除。

| 函数 | 用途 |
|---|---|
| **useTheme** | 主题状态单例：跟随系统/浅色/深色三态切换，持久化保存，全局响应 |
| **useLocale** | 语言状态单例：手选/跟随系统、运行时注册新语种、翻译取词 |
| **useFormat** | 格式化纯函数：手机号/姓名/银行卡/邮箱脱敏，金额千分位两位小数 |
| **useSafeArea** | 底部安全区单例：小白条/手势条高度，弹层垫底不再踩坑 |
| **useIconFont** | 图标字体注册：接入自有 iconfont，注册后与内置图标同用法 |

## 🌗 深色模式，三种粒度

| 粒度 | 说明 |
|---|---|
| **跟随系统** | manifest 开启暗黑支持后自动跟随；原生导航栏 / tabbar 配合 theme.json 联动 |
| **手动切换** | 浅色 / 深色 / 跟随系统三态任切，持久化保存，重启保留、跨页面生效 |
| **局部深色域** | 某块区域独立深色（深色卡片、键盘面板）：n-theme-provider 的 custom-style 整组覆盖中性色令牌（组件颜色全部走 var() 令牌，覆盖即生效） |

实现机制为 CSS 变量双主题：深色主题只重定义中性色，组件全部取变量值——切换零闪烁、无多余节点。

## 🌍 国际化

- 组件内所有文案（含弹层按钮、键盘键）统一走语言包，简体中文、英文随库发行
- **三层回退**：手选语言 → 应用/系统语言 → 内置中文，任何缺失键都回落中文，界面永不出现裸键
- 运行时注册新语种是正式扩展通道（标准 BCP 47 标签），库加密发行也不锁死语言
- 与 vue-i18n 等方案可共存：监听应用语言变化同步给库即可，库不依赖任何 i18n 框架

## 🎨 主题定制，三层覆盖

| 层级 | 手段 | 适用 |
|---|---|---|
| **运行时** | 节点上直接写 CSS 变量 | 动态换肤、局部微调 |
| **编译期** | 工程全局样式覆盖令牌默认值 | 整库品牌定制（主色、圆角、字号体系） |
| **默认值** | 库内置令牌表（styles/variable.scss，明文发行） | 直接使用，也是定制的参考底本 |

定制通道边界清晰：组件根节点用 custom-class / custom-style 命中；内部节点开放行内样式属性；插槽内容天然在页面作用域。哪些能改、怎么改，每个组件的文档写明白，不猜。
